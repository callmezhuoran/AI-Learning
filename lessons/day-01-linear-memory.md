## 原始任务

设输入和线性层为：

```text
X：[2, 16, 1024]，即 [batch, seq, hidden_dim]
线性层：1024 → 4096，包含 bias
精度：FP32
```

计算输出形状，权重与 bias 参数个数，参数、输入、输出的字节数和 MiB；预测 seq 翻倍与 FP16 的影响。可用 PyTorch 的 `numel()` 和 `element_size()` 验证，没有 PyTorch 时可先用普通 Python 验证算术。

## 已确认的理解

学习者正确解释了：

- `[2, 16, 1024]` 对应 batch、seq、hidden_dim。
- 权重参数为 `1024 × 4096`，加上 `4096` 个 bias。
- 计算可写成矩阵乘法再加 bias。
- seq 从 16 改为 32 不改变参数个数，输入与输出元素数翻倍，数学上的乘加次数翻倍。
- 在纠正存储与参数个数的区别后，正确回答：1B = 10 亿参数；纯权重 FP32 占 4 GB，FP16 占 2 GB；切换精度不影响参数个数。

## 标准表述与计算

对每个 token，每个输出特征由输入的 1024 个特征加权求和，再加一个 bias，总共生成 4096 个输出特征。

按 PyTorch `Linear` 的权重布局：

```text
X：    [2, 16, 1024]
W：    [4096, 1024]
bias： [4096]

Y = X @ W.T + bias
Y：    [2, 16, 4096]
```

所有 batch 和 token 共享同一组 W 与 bias。bias 广播到各位置，不为每个 token 单独保存一份参数。也可以将输入看成 `[32, 1024]` 进行矩阵乘法，再恢复输出形状。线性层变换每个 token 的特征，本身不混合不同 token 的信息。

```text
参数个数 = 1024 × 4096 + 4096 = 4,198,400
存储字节数 = 元素个数 × 每个元素的字节数
1 MiB = 1024² 字节
```

| 对象 | 元素数 | FP32 存储 |
|---|---:|---:|
| 权重＋bias | 4,198,400 | 16.015625 MiB |
| 输入 | 32,768 | 0.125 MiB |
| 输出 | 131,072 | 0.5 MiB |

这些仅是张量自身的存储，不包括梯度、优化器状态、临时空间或框架开销。

## 已纠正的误区

最初将“切换到 FP16”描述为“参数量减半”。修正后应表述为：每个元素由 4 字节变成 2 字节，参数存储减半，参数个数不变。

另一个术语修正：“输入和输出参数”应改成“输入和输出张量的元素”。本例参数是 W 和 bias；输入与输出属于处理数据时的张量，通常归入激活。

| 改动 | 参数个数 | 参数存储 | 输入／输出存储 | 数学上的乘加次数 |
|---|---|---|---|---|
| seq：16 → 32，精度不变 | 不变 | 不变 | 翻倍 | 翻倍 |
| 所有张量 FP32 → FP16，形状不变 | 不变 | 减半 | 减半 | 不变 |

数学上的计算次数不变，不意味着耗时不变；实际速度还依赖硬件、kernel 和访存，尚未对此进行实测。
